A packaging fix for 1.1.0, plus an Intel Mac build. The app itself is unchanged.

## Fixes

- **macOS: the app opens again after downloading.** 1.1.0's macOS app had a broken signature, so macOS reported it as damaged and offered no way to open it. The app is now properly signed ad hoc. macOS still asks once, because it isn't notarized: see below.

## New

- **Intel Macs:** a native `darwin-x64` build sits next to the Apple silicon one.
- **Automated releases:** a release workflow now builds every installer, on its own platform, from the release tag. It publishes them with `SHA256SUMS.txt`, and it is ready to sign them once signing is set up.

## Downloads

| Platform | File |
|---|---|
| Windows x64 | `jswallet-1.1.1-Setup-x64.exe` |
| macOS, Apple silicon | `jswallet-darwin-arm64-1.1.1.zip` |
| macOS, Intel | `jswallet-darwin-x64-1.1.1.zip` |
| Linux x64 | `jswallet_1.1.1_amd64.deb`, `jswallet-1.1.1-1.x86_64.rpm` |

Check a download with `shasum -a 256 -c SHA256SUMS.txt --ignore-missing`.

**The installers are not code-signed yet.** The system warns the first time you open them:
- **macOS:** System Settings › Privacy & Security › **Open Anyway**. On macOS 14 and older, right-click › **Open**.
- **Windows:** SmartScreen › **More info** › **Run anyway**.

Windows signing (through the SignPath Foundation) and Apple notarization are planned.

JSWallet is an educational wallet and runs on testnet4 by default. It is not production software.
